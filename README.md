# Literature Logic Chain

这是一个面向**计算机基础薄弱的文科生**的 Codex Skill。

它的核心目标不是“把论文总结得很短”，而是把算法论文按照**人类真正理解事物的顺序**讲清楚，让读者能够顺着网页从：

> 作者在解决什么问题 → 为什么原来的方法不够 → 作者发现了什么 → 这个发现如何变成训练任务 → 数据为什么这样处理 → 每个模型到底负责什么 → 为什么必须这样设计 → 不这样做会怎样 → 训练完得到什么 → 最终怎么使用 → 实验究竟验证了哪一个说法 → ablation 如何做反事实检验 → 论文真正证明了什么 → 哪些地方仍然不知道

一路读下来。

## 设计原则

### 1. 内容优先于功能

网页首先是“可连续阅读的论文讲解稿”，其次才是可视化页面。

### 2. 不把完整解释压成关键词

像下面这样的内容不能作为主要解释：

```text
Why: 防止信息泄漏
Function: 学习 style
If omitted: entanglement
```

必须展开成自然语言，让没有计算机基础的读者理解“为什么”“怎么做”“为什么不这样做”。

### 3. “一句话逻辑”改为完整开场段

页面开头使用：

> **先用一段完整的话把整篇论文讲懂**

建议 250–500 个中文字符左右，完整覆盖问题、现有方法不足、关键观察、数据/模型设计、最终任务和实验验证。

### 4. 前置知识只展示词条

前置知识只告诉读者需要准备哪些概念，不做大卡片、不做课程、不占用页面大面积。

例如：

```text
AI 文本检测 · Paraphrase · Embedding · Transformer / BERT · SBERT
Encoder / Decoder · LoRA · InfoNCE · OOD Detection · DeepSVDD · AUROC
```

正文第一次遇到这些概念时，再用人话解释到足以理解当前论文的程度。

## Codex 中的使用

全局 skill：

```text
~/.agents/skills/literature-logic-chain/
```

当前仓库 skill：

```text
.agents/skills/literature-logic-chain/
```

推荐调用：

```text
$literature-logic-chain

请从头到尾阅读这篇论文。
我的计算机基础比较薄弱，请不要用摘要式、术语堆砌式的方式解释。
一定要按照人类认知顺序，从“作者为什么研究这个问题”开始，一步一步解释：
为什么现有方法不够、作者发现了什么、如何把这个想法变成数据和模型、每个模型具体负责什么、为什么必须这样设计、不这样做为什么不行、实验分别在验证哪一个说法、ablation 说明了什么，最后说明论文证明了什么和没有证明什么。

开头请先用一整段完整的话把全篇逻辑讲懂，不要为了“一句话”而压缩成口号。
前置知识只列词条即可。
最后生成一个蓝色系、可直接阅读、可交互的独立 HTML。
```
